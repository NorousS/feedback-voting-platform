
# MVP платформы отзывов и голосований

## 1. Цель MVP

Основная задача первой версии — дать посетителю возможность открыть опрос, выбрать ответ, проголосовать и сразу увидеть обновлённые результаты. Также доступны создание простого опроса и отправка отзыва.

## 2. Use case UC-01 «Проголосовать в опросе и увидеть результат»

**Актор:** посетитель платформы без авторизации.

**Предусловия:** запущены frontend и backend, в системе есть хотя бы один опрос с двумя или более вариантами ответа.

**Основной сценарий:**

1. Посетитель открывает страницу `/surveys`.
2. Видит список опросов и выбирает один из них.
3. Открывается страница `/surveys/:surveyId` с вопросом и вариантами.
4. Посетитель выбирает один вариант ответа.
5. Нажимает кнопку «Проголосовать».
6. Frontend отправляет запрос `POST /api/surveys/:id/votes`.
7. Backend проверяет опрос и вариант, увеличивает счётчик голосов на один.
8. Frontend переходит на `/surveys/:surveyId/results`.
9. Посетитель видит общее число голосов, голоса по вариантам, проценты и горизонтальные диаграммы.

**Ожидаемый результат:** голос принят, результаты пересчитаны и показаны пользователю.

**Альтернативные сценарии:**

- Вариант не выбран — появляется сообщение «Сначала выберите вариант ответа», запрос не отправляется.
- Опрос не найден — API возвращает 404, интерфейс показывает ошибку.
- Вариант ответа не существует — API возвращает 400, голос не учитывается.
- API недоступен — интерфейс показывает сообщение об ошибке, приложение не падает.

## 3. Дополнительный use case UC-02 «Отправить отзыв»

**Актор:** посетитель платформы.

**Предусловия:** открыта страница `/feedback`, API доступен.

**Сценарий:** посетитель вводит текст отзыва, при желании имя, нажимает «Отправить отзыв». Сервер сохраняет отзыв в оперативной памяти и возвращает подтверждение.

**Результат:** пользователь видит сообщение об успешной отправке.

**Альтернатива:** если текст пустой, появляется сообщение об ошибке.

## 4. Границы MVP

**В первую версию входят:**

- интерфейс React 19 и маршрутизация;
- список опросов, детальная страница и выбор ответа;
- сохранение голоса через Node.js API;
- результаты голосования с процентами и диаграммами;
- обработка основных ошибок;
- создание опросов и отправка отзывов;
- общая библиотека компонентов `ui-library`;
- временное хранение данных в `backend`.

**За пределами MVP остаются:**

- регистрация, авторизация и роли;
- постоянная база данных;
- защита от повторного голосования;
- модерация отзывов и расширенная аналитика;
- экспорт результатов и уведомления.

## 5. Критерии готовности для лабораторной № 6

- Сценарий UC-01 выполняется полностью от списка опросов до результатов.
- Приложение работает без ошибок консоли и необработанных исключений.
- Ошибки ввода, отсутствующего опроса и недоступного API отображаются понятно.
- `frontend`, `backend` и `ui-library` используют TypeScript и ES-модули.
- Команды `npm run build`, `npm run dev`, `npm run lint`, `npm run test` проходят без ошибок.
- Покрытие хотя бы одного разрабатываемого компонента составляет не менее 90% по всем четырём показателям. Компонент `Button` покрыт тестами на 100%.
- В `README.md` указаны запуск, демонстрация UC-01 и реальные скриншоты.
